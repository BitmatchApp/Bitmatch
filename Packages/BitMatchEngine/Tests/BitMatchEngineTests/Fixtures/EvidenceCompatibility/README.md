# Evidence compatibility corpus

All media bytes are tiny, original synthetic payloads, generated by `Scripts/ascmhl/create_compatibility_fixtures.py`. No camera footage, personal hostname or production metadata is included. The fixtures and handcrafted reports/classic-MHL example are offered under BitMatch's MIT license.

`reference/` was generated with the official [ASC MHL reference implementation](https://github.com/ascmitc/mhl) at commit `0fb61f1e4c7c1c3ff422449aa6f091ce0d3b7687` on October 10, 2026. Its MIT notice is retained in `ASC-LICENSE.md`. The manifests are output from that tool, not BitMatch's writer. MD5 contains two generations; XXH64 and C4 contain one. Each inventory and chain passed the official XSDs, `ascmhl-debug verify` and `ascmhl diff`. The CLI's own timestamp/version fields are retained; the hostname is replaced before generation.

Regenerate into a new, empty directory using a Python 3.11+ environment with that pinned checkout installed:

```
python Scripts/ascmhl/create_compatibility_fixtures.py /tmp/new-bitmatch-evidence-fixtures
```

The tests copy fixtures into disposable roots. MD5/XXH64, zero-byte files, Unicode/XML escaping, filename whitespace, nested roots and two generations must retain every expected path. Changed/missing media must fail; additional files are informational. C4-only entries are explicitly unsupported, including beside supported records. Tests derive corrupt, duplicate, unsafe-path, failed-action, foreign-namespace, future-version, prefixed-namespace, entity and nested-metadata variants without changing these originals.

`reports/` captures current, older, extended, Quick, unsafe, unknown-method, unknown-algorithm and truncated JSON. Only current and compatible extra-field snapshots may supply a verified saved-report status. These handcrafted snapshots test reader compatibility; they are not fresh verification evidence or output attributed to an external offload application.

`classic-v1.mhl` documents the current unsupported format. BitMatch still discovers ASC inventories under `ascmhl/`; this batch does not add standalone classic-MHL discovery or claim full chain, rename or directory-hash verification. ASC checks explicitly describe their file-content scope. Histories are never rewritten by these checks.
