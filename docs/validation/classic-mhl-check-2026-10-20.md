# Classic MHL content checks — October 20, 2026

Check can discover standalone classic MHL 1.1 inventories when its existing BitMatch-report and ASC evidence paths supply no records. Existing evidence precedence remains in place; damaged or unsupported ASC evidence cannot be bypassed with a narrower classic inventory. Classic records inside `ascmhl/` remain unsupported.

Each recorded path is relative to its own manifest folder, including nested inventories. The reader combines consistent MD5 and SHA-1 records for the same path and requires every supplied digest and the recorded size to match. Conflicting sizes or digests fail discovery. Filename whitespace is preserved; canonically equivalent but byte-distinct recorded names are rejected rather than silently merged.

Classic results say “matches recorded checksums.” Manifest dates do not establish when copying occurred. The shared Mac, iPad and iPhone presentation states that file contents were checked while copy history and authenticity were not verified. Additional files remain informational; missing or changed recorded media prevents an intact result. Contributing manifests are omitted from the extra-file list by exact URL.

The same presentation change normalizes ASC history-directory paths before comparing them with validated chains. URL directory flags no longer make a fully checked inventory chain appear only partly checked. Both URL forms retain the explicit limits on directory structure and authenticity; this does not widen the engine's chain-validation scope.

## Read-only safety and limits

Manifest and media reads use pinned descriptors. Named files and ancestors are checked without following user-controlled symlinks; only the fixed macOS `/private` aliases are tolerated. Both media digests run in a single streaming pass with bounded buffers. File identity is checked after reading and again before completion. Manifest identity and SHA-256 are rechecked before and after media checks, so even a same-byte replacement invalidates discovery. Files, histories and publication status are never rewritten by Check.

Cancellation checks run through candidate collection, parsing and each media chunk; pause applies to media reads. A synchronous OS read already in progress cannot be forcibly interrupted. This feature does not change transfer verification, source-health decisions, recovery or safe-to-erase policy.

The supported format is UTF-8 classic MHL 1.1 with MD5 and/or SHA-1. UTF-16, other declared encodings, DTD/entity declarations, processing instructions, signatures, referenced histories, unknown hashes and versions, unsafe paths and ambiguous records fail explicitly. This is a bounded content reader, not full schema validation or broad third-party certification. Dates are informational. The reader deliberately accepts zero-byte files: their empty-content digests are meaningful, although the original v1.1 schema declares size as `positiveInteger`.

Accepted classic evidence is limited to 64 MiB of aggregate candidate XML, 1,024 manifests and 100,000 unique expected files. Each parsed manifest is also capped at 100,000 unique paths and 250,000 hash records. Path text is limited to 4,096 UTF-8 bytes, metadata fields to 64 KiB, digest fields to 256 bytes and the XML declaration to 1,024 bytes. These bounds do not limit the existing folder enumeration or total History size. ASC directory/root hashes, rename lineage, custody authentication, source-provenance verdicts and history extension remain outside this feature.
