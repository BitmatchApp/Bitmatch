# Classic MHL duplicate timestamp consistency — October 20, 2026

Classic Check combines repeated records for the same byte-identical relative path so separate MD5 and SHA-1 rows can contribute their digests. Size and digest disagreements already fail discovery. This slice adds the same boundary for contradictory, parseable `lastmodificationdate` values. It is a consistency check on claims in the inventory; Check does not compare these dates with filesystem timestamps, and dates do not prove when a copy occurred.

The comparison uses parsed ISO 8601 instants. Equal instants are accepted across timezone spellings and fractional-second spellings, including a whole-second value and the same value written with `.000` fractional seconds. Distinct parsed instants fail closed; the comparison applies no time tolerance. It uses Foundation’s parsed `Date` values, without claiming finer timestamp precision than that parser retains. An empty or unparseable timestamp contributes no parsed date, so it does not contradict a parseable value. The element itself remains required by the reader's supported-record shape: omitting `<lastmodificationdate>` is still unreadable evidence. Other record requirements, digest checks, path safety and evidence precedence are unchanged.

A subsequent review found an ordering gap in that tested revision: an empty or unparseable timestamp between two conflicting valid dates could replace the first date with `nil`. The reader now preserves a prior parsed date when merging a record without one. Four parameterized regression cases cover empty and malformed middle rows in both orders. ## Scope and limits

This rule resolves contradictory metadata when several rows are merged for one path. It does not authenticate the manifest, establish custody, prove copy history, validate a timestamp against the file, or turn classic MHL into an ASC history. Unsupported formats still fail closed. No additional classic-format fixture was imported in this slice: the reviewed historical source tree has an Apache license but does not include the advertised generator implementation or a sample manifest, so its output lineage cannot be reproduced or audited from source. Independent classic-fixture coverage remains open work. The existing classic reference corpus and its provenance/licensing receipt remain authoritative for that fixture's origin.
